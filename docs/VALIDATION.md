# 预览版测试记录

2026-11-08，在独立、无头、一次性的 Android 15 AOSP x86_64 模拟器测试。API 35，系统构建 `AE3A.240806.019/12368160`，root adbd。没有连接或安装到用户手机；没有使用用户的实际 APK、数据或账号作为测试内容。

## 集成场景

使用本地签名的最小测试 APK，占用三个目标包名；另建一个非目标测试应用。

| 场景 | 结果 |
| --- | --- |
| 三个目标原状态保存、整包禁用并停止 | 通过 |
| 目标与非目标共享 UID、但进程独立 | 非目标 PID 保持不变，防火墙规则不变 |
| APK 与私有数据保留 | 三个目标 APK SHA-256 不变，四个应用私有标记文件内容不变 |
| 人工重新启用目标 | 系统包回调触发再次禁用，原始状态文件未被覆盖 |
| 更新目标 APK | 继续保持禁用，私有标记文件仍在 |
| 新 Android 用户安装目标 | 自动隔离；恢复后回到该用户原始状态 |
| 目标与非目标已经共用同一进程 | 不杀共享进程，中文状态明确报告尚未完全隔离 |
| 停用模块 | 原 enabled 枚举（包括显式 enabled=1）与 stopped 值准确恢复 |
| 原状态文件损坏 | 拒绝修改包状态，不覆盖为猜测值 |
| 模块目录移走 | 保留的恢复控制器与开机恢复脚本仍能恢复 |

运行命令：`python3 tests/integration.py --serial <一次性模拟器序列号>`。测试脚本中短暂等待是测试驱动的观测过程，未打包到模块中。测试只准接收 `emulator-*`，并验证 qemu 属性及 root 身份。

## CPU 与内存

最终控制器的 30 秒空闲窗口中，`/proc/<pid>/stat` 的 user＋system CPU 计数增加 **1 jiffy，即 10 ms CPU 时间**，系统 `CLK_TCK=100`；此前两轮为 0 jiffies。最终 PSS 为 **47,153 KiB，约 46 MiB**，含 Java 运行时。采样分辨率是 10 ms，不能解释为物理意义上的零耗电。

重新启用后的自动禁用，在已完成的运行中约 **0.38–0.62 秒**确认；该数值包含 adb 命令和状态查询启动开销，不是严格的回调延迟分布或时延保证。

没有测量物理手机电流、每日电量百分比、长时间深度休眠或厂商待机策略。低耗电判断来自“无固定轮询、无唤醒锁、无网络、事件到达才执行”以及上述短时 CPU 观测。

## 未覆盖

- HyperOS 真机、真实 UID 1000 的系统组件、实际系统安全功能的兼容性。
- Magisk / KernelSU / SukiSU 完整管理器安装、实际重启及卸载流程。已通过安装脚本模拟宿主（真实 API 预检、拒绝运行中原版的目录检查）、恢复入口和模块目录缺失场景，不能等同于上述平台端到端验收。
- 厂商拒绝禁用关键包、特权应用反复重新启用、系统服务重启后的自动重新注册。模块会保留已禁用状态并显示观察器是否运行，没有循环重试守护。

这是可审查、可恢复的预览实现，不是已完成真机认证的版本。
